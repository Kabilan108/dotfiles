# Explainer recipe

Use this to teach how a system, feature, or failure works.

- One-sentence mental model and intended reader.
- Provenance: files, commits, runtime observations, documents, and commands actually examined.
- Request path or state transition in numbered order.
- Diagram with a legend when relationships are easier to understand spatially.
- Key modules and interfaces with file and line anchors.
- Focused source snippets behind collapsible details when they support the explanation.
- Gotchas, failure modes, invariants, and boundaries.
- Glossary or FAQ only when the vocabulary is genuinely domain-specific.

Interactive models are optional. If used, expose current state, provide reset, support the keyboard, and export the resulting configuration or prompt.
