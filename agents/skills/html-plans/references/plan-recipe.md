# Plan recipe

Use this for implementation and migration plans.

1. Lead with the outcome, current constraint, scope, and non-goals.
2. Show the current and target flow. Use Mermaid for topology or sequence; use cards when descriptions matter more than edges.
3. Break work into independently reviewable milestones. For each: files/surfaces, behavior, acceptance checks, dependencies, and rollback boundary.
4. Include only the snippets that explain risky interfaces, migrations, state transitions, or reconciliation.
5. Add a risk table with likelihood, impact, mitigation, and verification.
6. Record open decisions with owner or deciding evidence. Do not disguise unresolved choices as implementation details.
7. Finish with test strategy, rollout, rollback, observability, and definition of done.

Optional: low-fidelity UI sketches, effort ranges, data migration examples, compatibility matrix, or a decision comparison with a recommendation and revisit condition.
