Six things not to miss

The shortest useful read.

Audio is not a mixer yet.

One output slider, mute, and a passive input label. There is no current media UI.

Notifications have no unread model.

The service is capable, but the center cannot express read state and has ambiguous history actions.

Wi-Fi exposes dead controls.

The production service returns unavailable for scan and radio toggle.

Battery uses the wrong danger token.

The widget reads status.error; theme v2 defines status.danger.

Agent warm reopen is source-only.

The optimized helper passed tests, but the active closure still has the older hide behavior.

Recording hides existing actions.

Meeting finish, cancel, rename, dismiss, and result actions exist below the UI.

Audio + media

PipeWire · Mod+A · bar

Partial
Works
  • Default output volume and mute
  • Output/input names
  • Media keys through playerctl
Missing or misleading
  • No device switching or input controls
  • No per-app streams
  • No MPRIS panel; “Mixer” is one slider
Choose

Audio-only or audio + media; device switching; per-app streams; amplification above 100%; compact media summary or full player.

Evidence

AudioService.qml:13–64 · audio/Panel.qml:11–31 · Niri bindings 497 and 518–528. D3 exercises the service contract, not this real panel.

Notifications + DND

D-Bus owner · Mod+N · warm

View rebuild
Works
  • Replacement, timeout, history, actions
  • Multi-output routing
  • DND policy and restart recovery
Missing or ambiguous
  • No unread/read state or bar indicator
  • Center close re-archives instead of removing
  • Expired action buttons remain visible
Choose

Unread treatment; mark-read behavior; toast dismiss vs history delete; expired-action treatment; whether DND hides current toasts.

Evidence

NotificationService.qml:18–147, 203–456 · NotificationCard.qml:127–195 · generated DND settings are not consumed. Notification suites passed; live shell is the sole D-Bus owner.

Network + Bluetooth

NetworkManager · BlueZ · bar / Mod+Alt+B

Scaffold
Works
  • Wired and connected-network status
  • Saved/open network activation
  • Bluetooth power, discovery, connect
Missing or misleading
  • Wi-Fi Scan and radio toggle are dead
  • No secured/hidden join or VPN
  • Bluetooth off conflates disabled and idle
Choose

Native credential flow or applet handoff; VPN scope; paired/nearby grouping; battery/trust/forget states; whether the legacy applets remain.

Evidence

NetworkService.qml:11–51 returns unavailable for production scan/radio/VPN actions. network/Panel.qml:8–18 still exposes them. D3 fakes these actions and does not prove production behavior.

Battery + power + resources

UPower · power-profiles-daemon · /proc

Mixed
Works
  • Battery percentage, state, low threshold
  • CPU and memory sampling every 3 s
  • Bar-routed lazy panels
Missing or misleading
  • External profile changes never refresh
  • Profile failure has no rollback or error
  • Read failure looks like zero usage
Choose

Battery detail depth; reactive profile state; CPU/memory only or more resources; battery-watcher ownership; bar-only or direct access.

Evidence

PowerService.qml:17–37 samples once and updates optimistically. battery/Widget.qml:13 reads the nonexistent status.error. D3/D4 passed.

Agent panel

Ghostty · persistent tmux · Mod+` + bar

Working
Works
  • Fixed, injection-resistant launch contract
  • Persistent stillsuit-agent session
  • Niri placement, focus, deduplication
Missing or misleading
  • Bar has no opening/busy/failure state
  • Middle-click status has no visible result
  • Warm-reopen optimization is not active yet

Visible lifecycle states; keep or remove secondary clicks; preserve 72% geometry; immediate dispatch vs settled result.

Evidence

AgentPanelWidget.qml:12–39 always renders “⌁ AI”. Helper fixtures, shell syntax, and Niri validation passed. Current status: tmux running, window absent, no launch pending.

Recording + meeting

gpu-screen-recorder · durable worker · Mod+Alt+R

Thin UI
Works
  • Start, pause, resume, finish
  • External state survives shell reload
  • Durable meeting enqueue and recovery
Missing or misleading
  • No “finish as meeting,” cancel, or rename
  • No capture setup controls
  • No meeting retry, progress, or durable access
Choose

Distinct meeting finish; capture setup depth; completion actions; failed-job retry; progress and job identity.

Evidence

RecordingService.qml:147–173 exposes more actions than RecordingPanel.qml:76–88. D4/D5 passed; the real GPU/Siren/Codex pipeline was not rerun for this review.

Decision queue

Conversation order, not implementation order.

  1. Audio + media — decide the panel boundary and device/stream depth.
  2. Notifications — settle unread, dismissal, and historical actions.
  3. Network + Bluetooth — choose native credentials versus applet handoff.
  4. Recording + meeting — choose the intended capture-to-minutes workflow.
  5. Power + resources — choose how much detail earns permanent UI.
  6. Agent — keep behavior; add only the lifecycle feedback you want.

After each conversation, accepted choices can be converted into small implementation lanes with explicit ownership and tests.
