What “legacy parity” means

The old Stillsuit surface was a full player, not a summary: cover art, title, artist, album, seek position and duration, shuffle, previous, play/pause, next, and repeat. It also exposed output and input levels plus output-device selection. The new panel can be visually tighter without losing those controls.

Input controls

“Output switching only” settles device switching, but not whether microphone level and mute remain available.

Implementation evidence

Legacy NowPlaying.qml contains full transport, metadata, art, seek, shuffle, and repeat. Legacy AudioMixer.qml contains output/input levels and output selection. The current Next panel exposes only one output slider and mute.

Network + Bluetooth

Native common path, explicit fallback for uncommon credentials

3 choices
Locked direction
  • MobergAnalytics is an allowlisted quick VPN toggle.
  • Any other active VPN/tunnel appears as read-only active state.
  • Tailscale shows running state, this device’s Tailscale IP, and tailnet name; no controls.
  • Bluetooth uses connected, paired, and available groups with honest transition and failure states.

Native credentials vs applet handoff

Native

Looks coherent and can show scanning, password, joining, wrong-password, and failure in place. It also makes Stillsuit responsible for secret handling and every NetworkManager branch.

Applet/editor handoff

Delegates unusual credentials to mature NetworkManager UI. It is lower risk but visually disjoint, and an applet-only design needs a tray or a separately launched editor.

Omarchy Quattro already implements a native common path: saved/open networks connect directly, personal secured networks use an inline password, and enterprise credentials fall through a dedicated helper. Adapting personal Wi-Fi plus an enterprise/hidden fallback is a medium lift. Owning every enterprise and hidden-network branch natively is a high lift.

Bluetooth battery

Show percentage on connected devices only when BlueZ reports it. Never synthesize an unknown value.

Trust and Forget

Trust is a BlueZ reconnect authorization flag; pairing should set it automatically. Forget disconnects and removes the stored bond/trust record, so the device must pair again.

Battery + power + resources

Useful laptop state without a diagnostics dashboard

3 choices
Locked direction
  • Resources are CPU and memory only.
  • Profile changes made outside Stillsuit must appear in the panel.
  • Profile changes show pending state; failure restores the daemon’s real value and explains the error.

Reactive profile state

Refresh when the panel opens, periodically while visible, less often while hidden, and after every action. A change made by a keyboard command or another app therefore reaches the UI instead of leaving a stale selection.

Battery watcher ownership

Low/full battery alerts should outlive shell reloads. Today a Niri startup child polls every minute. A user service would own dedupe and thresholds; Stillsuit would only display the notifications.

Bar-only vs direct access

This asks only how the panel opens: click the battery/resource cluster, or also reserve a keyboard/IPC shortcut. It does not change the data shown.

Available battery detail

UPower can provide health/capacity, cycles, live draw, and charge thresholds in addition to percent, state, and time remaining.

Agent panel

A keyboard-launched terminal surface, not bar status

One choice
Locked direction
  • Remove the agent widget from the bar entirely.
  • Remove its right-click hide and middle-click status paths with it.
  • Keep Mod+`, Ghostty, and the persistent stillsuit-agent tmux session.
  • The helper waits for mapping/focus internally; the key binding does not need a visible result.

Middle-click status

The current bar widget asks the helper for session/window state but has nowhere to show the answer. It serves no purpose after the widget is removed.

Secondary clicks

This meant right-click to hide and middle-click for status. Both belonged to the bar widget, not the terminal panel.

72% geometry

The current Niri rule opens the agent window at 72% of output width and 72% of output height. It is simply the panel’s window size.

Dispatch vs settled result

“Immediate” returns as soon as launch starts; “settled” waits until Niri reports the window mapped and focused. This remains an internal reliability detail.

The warm-reopen optimization is already implemented and tested in source. It keeps the Ghostty application warm and asks it for a new window instead of cold-starting the process. It becomes active only after a future user-run rebuild plus the planned shell/session transition; this review will not activate it.

Recording + meeting

Restore capture controls and make post-capture work recoverable

3 choices
Locked direction
  • Return toward the old custom indicator: recording dot, pause state, elapsed time, and deliberate hover treatment—restyled with the approved theme.
  • Setup includes output, title, desktop audio, and microphone controls.
  • Active actions include pause/resume, finish as meeting, normal finish, and cancel.
  • Meeting jobs expose stage/progress, stable identity, durable access, and retry after failure.

Capture setup

Choose the output/monitor, name the recording, include desktop audio by default, and opt into microphone capture. These controls existed in the older panel.

Durable access

A toast or completion state is temporary. Durable access gives you a later route back to completed or failed meeting work after the panel closes or the shell reloads.

Finish as meeting

Stops the recording and enqueues the durable minutes pipeline. Normal Finish stops and saves the recording without creating a meeting job.

Failed-job retry

Retries the durable meeting job from its retained recording and job metadata; it should never require recording the meeting again.
