Quattro shell, tastefully robbed.

How Omarchy 4 turned a desktop into one extensible Quickshell host. This report takes its best boundaries, lifecycle contracts, theme graph and components without importing its distro policy or sanding off Stillsuit's own character.

00 · Executive call

Steal the host. Keep the suit.

Do not wrap Omarchy's shell as the new desktop. Rebuild Stillsuit around the same architectural seams.

Quattro's durable contribution is not its colors or its exact bar. It is the separation between a long-running composition root, injected singleton services, versioned plugin metadata, typed contribution kinds, lazy surface loaders, a data-driven bar, shared UI primitives, one IPC facade, and a palette-to-adapter theme graph. Those ideas fit Nix extremely well once runtime Git, mutable source trees, Hyprland assumptions, and imperative config rewriting are removed.

Preserve

Stillsuit identity

Catppuccin character, compact glass language, the Niri workspace/column model, recording and meeting workflows, Dictator's live waveform, and notification policy.

Borrow

Quattro boundaries

Composition root, registry, manifests, lifecycle loaders, slot-based bar, injected context, service/view separation, safe fallback, and broad contract tests.

Refuse

Omarchy policy

Runtime plugin installation, mutable Git source, whole-file config rewriting, app config surgery, broad login-shell commands, and Hypr-only assumptions. Mise is outside the desktop effort.

The local work is not disposable. Stillsuit is already a functioning 7,264-line Niri shell with unusually good local workflows. The architectural rewrite should make those features easier to extend, not replace them with generic Omarchy equivalents.

02 · Runtime spine

One process, three loader branches.

Quattro launches one named Quickshell instance for the graphical session. The root owns the canonical service graph; manifests are discovered once; UI then fans into a selected full bar, singleton services, and on-demand surfaces.

UWSM environmentestablishes OMARCHY_PATH and session environment
→
Hyprland autostartinvokes the shell launcher once per graphical session
→
Launcher supervisorjournals output, restarts failures, suppresses unsafe QML tree reloads
→
ShellRootcreates registries, app library, config store, IPC and loaders
→
Plugin graphbar + services + panels / overlays / menus / widgets

Explicit ownership

The root instantiates exactly one PluginRegistry, BarWidgetRegistry, and AppLibrary, then injects those instances. This avoids accidental per-import singleton copies. shell/shell.qml:11–20

Warm surfaces

Panels are summoned by IPC into an already-running process. Loaders are active only while open unless a manifest requests keepLoaded. Pending payloads are queued until the async component resolves. shell/shell.qml:407–478

Graceful fallback

A broken replacement bar falls back to omarchy.bar; failed surfaces log and close; failed widgets release their load claim so a later rescan can retry. shell.qml:237–260, 640–649, 795–804

Focused-output routing

The bar exists per output, but keyboard summons route to the already-open widget or the compositor-focused monitor. This prevents duplicated IPC authority in multi-monitor layouts. Bar.qml:428–518

The root is already getting heavy. At roughly 1,030 lines, shell.qml owns config, plugin lifecycle, bar routing, service creation, theme IPC, compatibility and generic surface IPC. Copy the single composition root, but split Stillsuit's implementation into ConfigStore, PluginHost, SurfaceRouter and a small IPC facade.

03 · Plugin architecture

Metadata decides what exists; the host decides how it lives.

The manifest is deliberately small. It names an ID, version, contribution kinds and entry points. The host centralizes singleton versus per-output behavior, eager versus lazy loading, fallback, context injection, config placement and IPC.

  "id": "stillsuit.agent-usage",
  "name": "Agent usage",
  "version": "1.0.0",
  "apiVersion": "1",
  "kinds": ["service", "bar-widget"],
  "entryPoints": {
    "service": "Service.qml",
    "barWidget": "BarWidget.qml"
  },
  "capabilities": ["agent-usage-read"],
  "barWidget": { "defaultSection": "right", "allowMultiple": false }
}

barExactly one selected implementation; async custom loader; built-in fallbackWrap the current TopBar first, then permit alternativesNever render two exclusion-zone owners
bar-widgetComponent registered once, visual instance created per bar/outputClock, workspaces, meeting, recording, resources, agent usageShared service state must not multiply per output

This is the proposed Stillsuit contract, not Quattro's current agents manifest. Upstream declares the agents surface only as a bar-widget; Stillsuit should separate collectors and state into a service.

The clever pieces worth taking

Structural enablement

A widget is enabled by appearing in the bar layout; a full bar by bar.id; other third-party surfaces by a config entry. First-party infrastructure defaults on and records only deviations. PluginRegistry.qml:110–166

Stable replacement identity

A personalized clone can replace a built-in while old IPC callers keep using the built-in ID. The registry routes the stable identity to the active clone. This is a useful compatibility concept even if Nix overlays replace runtime cloning.

Uniform core and local extensions

Built-ins and dotfiles-owned additions use the same manifest contract. This keeps the extension path honest: agents can add a feature without learning secret-only composition hooks.

Component-load containment

Manifest errors omit one plugin; widget/panel/service load errors are caught; the rest of the shell continues. The containment ends at the QML engine boundary.

Where Stillsuit should improve the contract

  • Add a real apiVersion, host compatibility range, known-kind rejection, dependency declarations, and state-schema version. Capabilities document authority and review scope; they are not a pretend sandbox. Upstream requires version but does not use it.
  • Generate and validate the production registry from dotfiles-owned Nix store paths. Keep out-of-store source only as an explicit local development mode.
  • Inject one narrow context object: theme, compositor, services, panels, logger, settings and instanceId. Do not expose the root object's entire authority.
  • Separate declarative defaults from writable UI state. A generated defaults.json may be overlaid by a narrowly scoped runtime-overrides.json; the shell must never rewrite Home Manager-owned files.
  • Let stillsuitctl export-overrides produce a Nix-ready fragment so an interactive bar arrangement can be promoted back into declarative config.
  • Make surface lifecycle explicit as unloaded, loading, loaded, or error. Clear queued open payloads on hide, disable, error, and reload; Quattro can otherwise replay a stale payload after a summon-hide race.
  • Reload one changed development plugin. Quattro destroys every panel and service, unregisters every widget, and clears the global QML component cache for any plugin edit.

The trust boundary is the dotfiles repository. There is no community marketplace, runtime installer, remote update path, or arbitrary third-party loading. Plugins are normal reviewed repo changes authored by the user or their agents and materialized by Nix. Same-process isolation is therefore not a phase-one requirement. Keep manifest validation, lazy-load error states, fallback components and per-plugin reload because trusted generated QML can still be buggy. Upstream contrast: docs/omarchy-shell.md:76–80

06 · Notification engine decision

Keep Stillsuit. Borrow the data lifecycle.

Quattro has the cleaner snapshot and expiry machinery. Stillsuit has the safer action contract, better named-action UI, better DND policy and the actual notification center. A wholesale port would trade away working behavior and import a command-execution vulnerability.

ConcernKeep from StillsuitBorrow from Quattro

07 · Agent panel

The shell controls the quake panel. Ghostty renders it.

Quattro's in-shell agent feature is a usage widget and popup. Launching an agent opens a separate terminal with a stable app ID. That separation is correct: Quickshell cannot embed a normal Wayland terminal surface, and building a PTY emulator in QML would turn a small convenience into a terminal project.

Mod+Grave / bar buttoncalls the fixed agent toggle IPC action
→
Stillsuit controllerruns one Nix-built helper; no caller-supplied command strings
→
tmux sessionone persistent stillsuit-agent session owns Codex
→
Ghostty windowstable app ID io.stillsuit.AgentPanel
→
Niri rulefloats and focuses the window on the current output

Preserve cxf exactly, but stop depending on the alias

codex --yolo \
  --model gpt-5.6-sol \
  --config model_reasoning_effort=low \
  --config service_tier=fast

The alias lives behind the interactive-shell guard, and Bash does not expand aliases in a normal noninteractive shell. Do not launch bash -ic cxf. Home Manager should generate the exact executable plus argument list and a helper with only open, hide, toggle, status, and an explicitly separate terminate action. local .bashrc:224–227

Persistent session

Tmux owns Codex, so hiding or closing Ghostty does not kill the desktop agent. A named session also prevents duplicate agents and preserves its current directory.

Quake toggle

A helper serializes actions with a lock, locates the exact Niri window ID and focuses it on the current workspace. Hiding closes only the Ghostty window; the named tmux session persists and a later toggle launches a fresh terminal attachment.

Typed authority

The shell may request only a literal lifecycle action. It cannot change the command, working directory, model or prompt over IPC.

Usage later

Port the Codex collector and JSON watcher after the terminal workflow works. Collectors run outside Quickshell and write sanitized records with no credentials.

Quattro's launcher already uses a separate terminal and stable org.omarchy.agent app ID. It normalizes the working directory and maps tool-specific flags before launching. bin/omarchy-agent:34–104. Its usage plugin is a separate bar-widget contract backed by atomic JSON records, not the terminal controller. agents/manifest.json:1–38

The --yolo authority is intentional and already present in cxf. The panel should not broaden it. Use a fixed working root, keep QML free of credentials, and do not let notifications or arbitrary plugins inject prompts or command fragments. Crash assistance can arrive later through a reviewed structured file handoff.

08 · Agent-authored extensions

The plugin system is a coding interface, not an app store.

The intended workflow is deliberately local: ask an agent for a feature, let it change the dotfiles through the public extension contract, review the diff and activate it with the next explicit rebuild. There is no runtime discovery of community code.

09 · Local baseline

Strong visual system, hand-built extension registry.

The live check during this refresh found a healthy Stillsuit process, valid shell status, a live Niri event stream, and a passing niri validate. The problem is not that it fails to work. Every addition expands a fixed web of root, bar, IPC and policy edits.

Ownership conflict exists live today. Waybar is systemd-enabled while Niri also starts Stillsuit's top bar; both layer surfaces were present on the same output. Niri starts Stillsuit in a compositor scope, not a user service. Moving it to systemd without removing compositor startup in the same generation would create two hosts and two notification contenders. Ownership selection is milestone zero.

The old agent workspace is a cross-cutting feature. Complete removal covers workspace "agent", the acu.* routing rule, Mod+0 bindings, agent-workspace-pin package/service/script, TopBar special styling and the niri-computer-use skill's spawn --bg behavior, doctor check and recipes. Editing config.kdl can affect the live compositor through its out-of-store symlink, so implementation should stage this change without touching the tracked live file until the first user gate.

The coupling is visible in the local root: panel close coordination and string-name routing live at stillsuit/shell.qml:34–81, while eleven concrete surfaces are instantiated at stillsuit/shell.qml:131–182.

Local hazards to fix or fixture before the host migration
  • The installed legacy quickshell/osd tree contains a second dormant notification server. Launching it would compete for the D-Bus name.
  • stillctl reload kills, sleeps 200 ms and restarts without waiting for process exit, IPC shutdown or notification-name release.
  • Production still runs out-of-store source with an open-ended runtime command set. The store package needs exact runtime inputs and an explicit development mode.
  • Dictator reconnect stops permanently after 30 failures. The new service contract should recover when Dictator returns later.
  • Recording, meeting and Dictator state crosses strong process/file boundaries already. Version those records before moving views, and prove a shell restart cannot kill an active recording.

Configuration authority

Recommendation: immutable defaults plus narrow runtime overrides. Export overrides to Nix; never let the shell rewrite Home Manager-owned configuration.

Plugin trust

Recommendation: treat dotfiles-owned extensions like any other trusted shell code. Do not build a marketplace, installer or sandbox. Keep loader failure states and fallback for reliability.

Theme selection

Recommendation: one curated Catppuccin Mocha record selected on rebuild. Add runtime selection only after multiple immutable generations work.

Auth surfaces

Recommendation: keep swaylock/polkit outside the plugin-capable host for the first implementation.

Notification ownership

Recommendation: keep the D-Bus daemon in the small core or a dedicated process so it can be handed over and tested independently of optional UI contributions.

Code provenance

Recommendation: port selected MIT code with file-level attribution and a notice; do not vendor the whole desktop or erase history.

Development speed

Recommendation: preserve an explicit out-of-store dev mode on Jacurutu; production and rollback tests use the store package.

12 · Incremental implementation

Parallelize the code. Serialize ownership changes.

The speed strategy is to freeze a small version-one contract, give agents disjoint file ownership, preview the next shell under a separate Quickshell config ID and batch compositor/Home Manager changes into two deliberate user rebuilds. Every provider can fall back to its legacy implementation; the entire next backend can fall back to stillsuit-legacy. Nothing activates automatically.

Package legacy unchanged, add typed contracts and one Catppuccin Mocha generation, build the next host in true shadow mode, and implement the cxf extension plus authoring skill. The quake helper closes/reopens Ghostty while tmux persists; it does not reuse the removed workspace.

  • Shadow mode claims no production layer, D-Bus, recorder, meeting, lock or polkit authority.
  • Broken manifests and components omit only that extension and expose useful error state.
  • Repeated cxf toggles leave one tmux session and at most one Ghostty window.

Port and integrate the visible desktop

Wrap today's bar first; split shared services from per-output views; then move widgets, OSDs and panels in parallel slices. Integrate the supervised unit, Waybar decision, old workspace removal, cxf rule/binding and next providers behind one default-off option. Run the result under a separate config ID with one shared fixture matrix and screenshot checklist.

  • Per-output views never multiply global services, timers, sockets or IPC names.
  • Panel mutual exclusion, pointer/keyboard behavior and focused-output routing match baseline.
  • Exact Jacurutu evaluation/build passes; the active generation is still unchanged.

User gate A · desktop cutover and design inspection

Notify only when the full non-notification desktop is built. One explicit rebuild disables Waybar and Niri's direct shell startup, enables the supervised next host, removes the old agent workspace/watcher, enables cxf and selects the next bar, panels and OSDs. Notifications remain on legacy.

  • No agent workspace, pinning service or acu --bg promise remains.
  • One bar surface/exclusive zone per output; recording, meeting and Dictator behavior survive shell restart.
  • The user accepts density, hierarchy, hit targets, motion, panel placement and quake behavior.
  • Switching the backend option or prior generation restores the complete prior desktop.

Refactor notifications behind the disabled provider

Finish daemon/model/policy/view separation, replacement tracking, bounded history, expiry and corrupt-record isolation while preserving Stillsuit's action and DND semantics. Keep the next provider disabled through all fixture work.

  • Expiry, replacement, actions, DND, markup, images, history and multi-output policy pass fixtures.
  • omarchy-exec and every unknown executable hint remain inert.
  • Stop/wait/start/acquire and rollback steps are scripted and inspected.

User gate B · notification ownership handoff

Notify immediately before the only separate high-risk ownership transfer. The user rebuilds; the handoff stops legacy, waits for D-Bus release, starts next and verifies acquisition before callers proceed.

  • Exactly one expected org.freedesktop.Notifications PID at every transition.
  • Live replacement, action, timeout and DND smoke tests pass.
  • Rollback reacquires the name without leaving two daemons.

Soak, then clean up separately

Run 8–24 hour resource checks and retain the legacy backend through one stable period. Remove dormant OSD source, compatibility aliases, old QML and Waybar material only in a later reviewed cleanup. A second theme, menu replacement and agent usage telemetry remain later polish.

  • RSS, wakeups, child processes, descriptors and watchers remain within budget.
  • Whole-generation rollback is documented and tested before cleanup.
  • Cleanup shares no change with an ownership cutover.

Notification policy

Use the notify skill only for Gate A, Gate B, a genuine blocker requiring a user decision, or final success after the stability check. Each gate message names why input is needed, the exact command or inspection target, rollback and this plan's stable URL. Routine agent progress stays in the implementation log.

Explicit initial non-goals

  • No Omarchy installer, package updater, migration runner, Hyprland Lua config, background manager or full CLI port.
  • No removal of Stylix, Walker/Elephant, swaylock, wallpaper handling or polkit during the host migration.
  • No community-plugin marketplace, runtime plugin installer, remote catalog or mutable production plugin directory.
  • No mise evaluation or agent-tool ownership changes in this desktop effort.
  • No visual redesign while composition and state contracts are moving.
  • No automatic NixOS/Home Manager rebuild or restart of Walker/Elephant.

14 · Acceptance and rollout

Evidence ladder and definition of done.

Static

Manifest/schema validation; duplicate IDs and IPC targets; known kinds; entry points; API compatibility; theme completeness; provenance/license records; Nix option assertions; no stale agent-workspace references.

Isolated runtime

Temporary HOME/XDG directories; start one next-shell config; exercise list/open/close/reload/theme/config; inject broken fixtures and verify fallback without production layer, D-Bus or workflow authority.

Nix

Format and evaluate the exact Jacurutu closure; inspect generated registry/theme/units and runtime inputs; finish with nix build --no-link. Build and evaluation are not activation.

Niri/live

Run niri validate -c for binding/startup changes. At Gate A, check workspace removal, multi-output geometry, focused-output routing, layer ownership, panel exclusion and current workflows.

Recovery

Break each newest provider deliberately; prove component rollback, whole-backend rollback, no duplicate daemon, and a documented terminal recovery path.

Long-run

Compare 8–24 hour RSS, CPU wakeups, child processes, file watchers and model counts against the current Stillsuit baseline.
