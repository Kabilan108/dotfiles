Agent VMs on sietch

Membership in libvirtd gives everything running as kabilan passwordless root through qemu:///system. No agent uses that path. Agents run raw QEMU from Nix-built runners. The fleet-security workstream closes the root path (Stage A) and adds the agent account (Stage C). This branch keeps the later Stage B launcher, which moves agent VMs into a root-enforced box so a hostile guest gets less than kabilan. Agent VMs are for unfamiliar repos and sketchy work. No credential service will run in a VM on sietch: Vaultwarden and Executor are moving to the Pi. This branch changes no host.

Source of truth: docs/plans/agent-vm/policy.md. Isolated probe: docs/plans/agent-vm/probe.nix. Skill draft: docs/plans/agent-vm/skill-draft/SKILL.md (not installed).

Plan in three stages

Stage A · owned by fleet-security

In progress in the cheap-fixes PR, branch security/cheap-fixes. This plan is its spec.

Drop kabilan from libvirtd. Set qemu.runAsRoot = false. A mkBefore polkit rule makes org.libvirt.unix.manage ask for a password every time (AUTH_ADMIN) for wheel and returns NO for everyone else. The branch also gates the read-only monitor action. Tony undefined the downloads storage pool on 2026-10-29.

Agent workflows don't change, because none use system libvirt. Tony's virt-manager needs a polkit agent or virsh + pkttyagent.

Stage B · agent-vm launcher · this branch, later

Root-owned slot sockets that only the agent-vm group can open. Each launch becomes a systemd unit instance that runs the agent's system.build.vm runner as a per-slot agentvm<N> user. The instance gets a filesystem allowlist, a uid egress filter, no tailnet interface, memory/CPU/disk caps, a 12h TTL and cleanup. The slot count caps concurrency.

The proven niri QA flow carries over with env-var paths and a copy-in share/ dir.

Stage C · owned by fleet-security

Part of that workstream's sietch agent-account step, because it needs the separate agent user that step creates. /dev/kvm and the GPU nodes become group-only, and the agent account joins agent-vm, which makes the launcher its only fast path. No second general agent identity.

Stage A polkit rule 
security.polkit.extraConfig = lib.mkBefore ''
  polkit.addRule(function(action, subject) {
    if (action.id == "org.libvirt.unix.manage") {
      return subject.isInGroup("wheel") ? polkit.Result.AUTH_ADMIN : polkit.Result.NO;
    }
  });

Validation and rollout

  1. Probe (done): authorization and egress invariants in isolation.
  2. Stage B NixOS test before any rebuild. It boots a real system.build.vm guest through the socket and checks that guest→10.0.2.2 is rejected, QMP/VNC are reachable, stop over the control socket works, memory/TTL/disk caps fail the guest rather than the host, and -sandbox and the unit filters work with the runner's virtiofsd daemons.
  3. Desktop QA on sietch after Tony rebuilds. Re-run the niri agent-seat flow. Pass means virgl on the 3090, SSH on 127.0.0.1:2222, QMP screendump, rfbsrc capture and the share dir all work.
  4. Read-only checks (fleet-security, with Stage A). An agent shell can't open qemu:///system. Tony is prompted each time. libvirtd is gone from id after relogin and a tmux restart.

Stage A ships first through the cheap-fixes PR, because nothing agents do depends on it. Agents keep raw QEMU until step 3 passes, then the skill ships. Recovery: sudo systemctl stop agentvm.slice. Instances never autostart.

Step 2 must also clear QEMU, virgl and NVIDIA under the new SystemCallFilter, RestrictAddressFamilies, -sandbox and allowlist settings. Any relaxation it forces belongs in this doc.
