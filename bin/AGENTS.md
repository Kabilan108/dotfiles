# Scripts notes

## agent-op

- Do not treat `agent-op` as a security boundary. Agents run as the token file's owner; the service account's read-only vault scope is what limits them. The script exists to keep the token and secret values out of agent transcripts.
- Give the service-account token only to the op process `agent-op` starts for one command; never export it in a shell profile or pass it to the command op runs. While the variable is set, op signs in as the service account, so a profile export would silently switch Tony's own op sessions.
- Clear inherited OP_ variables with the `${!OP_@}` expansion, not compgen. The bash that env finds may lack the completion builtins.
- Review the argument checks after any op upgrade that changes its flag parser or env-file expansion. They mirror op's parsing: op expands dollar variables in env files from its own environment (which holds the token), takes a bare word before the separator as the command, and lets a value-taking flag consume the next argument even when it is the separator.

## Other scripts

- Rebuild sietch before expecting a change to `flake-update-pr` to run. `home/services/flake-update.nix` starts a Nix store copy of the script, so the weekly job never runs whatever an agent left in sietch's checkout.
- Keep `JOB_BUDGET` in `flake-update-pr` below `TimeoutStartSec` in `home/services/flake-update.nix`. The job makes three builds of up to `BUILD_TIMEOUT` (3 h) each when caches miss; the 9 h budget leaves one hour of the unit's 10 h for reporting and cleanup. Raising the build timeout, the budget or the number of host builds means raising the unit timeout too.
- In `update-app-pins`, exit 75 (EX_TEMPFAIL) only for a failure systemd should retry by itself; today that is a failed fetch. `home/services/update-app-pins.nix` sets `RestartForceExitStatus = [ 75 ]` with a 15 minute delay, and every other exit status waits for Tony.
- End every command that can fail inside `review` and `pin` in `rebuild` with `|| return 1`. `rebuild` calls `review` from an `if`, and Bash turns errexit off inside a function called from a condition, so `set -e` does not stop it there.
- Keep the terminal check at the top of `edit-block-list`. agenix replaces a secret's whole contents from stdin when stdin is not a terminal, and this command exists to edit the current list. To replace the list wholesale, call agenix directly.
- Never rsync into /vault/userdata/tracer-ingest on sietch, and never rewrite session frontmatter there without merging tags. `tracer-digest` keeps its processed state only in the `wiki:compiled` tag, which survives re-pushes because the receiver of a tracer push unions tags; a raw rsync overwrote them and made every session reprocess.
- Call `obsidian-reconcile` after writing a vault file from outside Obsidian, and ignore its exit status. Obsidian's file watcher misses some external writes (a mount and inotify race), which leaves the file out of metadataCache and hides it from task queries and TaskNotes. A fresh Obsidian launch scans the whole vault, so the script exits 0 when obsidian-cli is missing; it exits 1 when the eval call fails. Delete the script and its calls in `tracer-digest` and `meeting-minutes` once Obsidian's watcher is fixed.
- Bump `GENERATION_VERSION` in `meeting-minutes` whenever a prompt or a validation rule changes. Cached results are keyed on it, so a forgotten bump serves stale minutes.
- Before adding a name to `CODEX_EXPECTED_TOOLS` in `meeting-minutes`, check that the tool cannot act on the world. The current set passed for these reasons under Codex 0.166: exec runs JavaScript in an isolate with no file system or network and can call only the nested tools in the set; apply_patch is refused by the read-only sandbox with approvals off; the MCP resource readers have no servers configured; the last one is a clock. Codex 0.166 also keeps unified_exec on whatever the config says, and it is `shell_tool` in `CODEX_DISABLED_FEATURES` that removes the command tool. `docs/meeting-minutes.md` (Isolation) covers the rest.
- Report Siren progress in `meeting-minutes` through `set_phase` when the phase changes, not only through `update_status`. The phase must reach the durable job state as well as the current-status projection, or a shell reload erases the visible stage.
- Give `sync-agent-skills` no external command that Home Manager activation lacks. Activation (`home/shell.nix`) runs it with a PATH of bash, coreutils, diffutils, findutils, gettext, gnugrep, gnused, jq, ncurses and nix: no awk and no hostname. That is why it parses frontmatter with Bash builtins and reads its host name from the fleet.json that `modules/home/fleet.nix` generates. Add anything else to the PATH in `home/shell.nix`.
- Change `uses_cpa` and `cpa_command` in `tmux-resurrect-agents` together with the wrappers in `modules/home/cpa-clients.nix`. The wrappers exec the real binary, so tmux-resurrect saves the binary's command line; the script detects a wrapped agent from the environment the wrapper exported (the CPA base URL for claude, `CPA_API_KEY` for codex) and strips the leading model_provider override that codex-cpa adds itself.
