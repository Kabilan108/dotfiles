# Stillsuit services notes

- `BatteryService.qml` reads design capacity, cycle count and charge thresholds itself when the battery appears or changes state, debounced by 2000 ms (`detailRefreshDelay`), because Quickshell 0.3's `UPowerDevice` does not expose them. The delay is latency the user sees; drop the extra read when the binding gains those fields.
- `BluetoothService.qml` binds sink nodes through `pipewireTracker` only while a connect is selecting its audio output. PipeWire node properties such as `api.bluez5.address` are populated only on bound nodes, and binding every sink all the time is not needed.
- Keep the 500 ms `positionTimer` in `MediaService.qml` gated on a view holding a tracking ref. MPRIS players signal position only on seeks, so a visible progress bar needs the tick and nothing else does.
- `PowerService.qml` decides availability from one `powerprofilesctl list` probe, not from `PowerProfiles`, which reports Balanced even when power-profiles-daemon is absent. Setting a profile writes it optimistically and only logs a rejected D-Bus `Set`, so the service re-reads 750 ms after a write (`confirmTimer`) and rolls back.
- `NiriService.qml` runs `niri msg` reconciliation on stream start and on screen changes because niri's event stream resends workspaces and windows on connect but never carries outputs.
- Keep `_workspaceSchema` and the window schemas in `NiriService.qml` in step with niri-ipc's `Workspace`, `Window` and `WindowLayout` structs, with `Option<T>` fields accepted as null or absent. niri-ipc's own reducer asserts that referenced rows exist; here an event that fails the schema or names a missing row falls back to reconciliation, as does any event type niri adds later.
- `NetworkService.qml` enables a device's Wi-Fi scanner only while a panel or scan wants it. Quickshell lists unsaved networks only while the scanner is on, and an enabled scanner keeps requesting scans.
- The `sanityTimer` and helper-polling fallback in `NetworkService.qml` exist because Quickshell 0.3.1 does not recover after NetworkManager restarts and its device list goes stale. The check costs one `nmcli` call a minute; remove both once Quickshell recovers on its own.
- `MeetingService.qml` never edits the meeting-minutes worker's jobs.json queue file. The worker owns its queue; the service reads status and a bounded snapshot, and sends retry or discard through the helper only on an explicit user action, never while loading or after a reload, so a shell reload cannot duplicate or lose jobs.
- Keep `publish` in `RecordingService.qml` on its own process. The helper-backed actions (rename, dismiss) must stay available while an upload is in flight.
- `slackMessage` in `NotificationSource.js` (sender, message, channel beside the app name) and `sourceTint` in `NotificationPolicy.js` (FNV-1a hash onto an oklch hue at lightness 0.76, chroma 0.11) follow Hokum. Two sources that hash to nearby hues look alike; that is accepted.
