# Clipboard test notes

- Replace the offer constants in `collector_test.py` (`FIREFOX_*`, `CHROMIUM_*`, `QT_TEXT`, `FOOT_TEXT`, `WL_COPY_TEXT`) only from a fresh probe, never by guess. They are exact `wl-paste --list-types` output, duplicates and order kept, recorded on Wayland on 2026-10-05 from Firefox 157, Chromium 154 and the Bitwarden extension 2026.9.3 with the vault at `https://localhost:8222`. The collector's shape hash covers duplicates and order, so a tidied list tests an offer no browser sends.
- Pass `--type` to `wl-copy` when a test copies a lone NUL, as `e2e-headless.sh` does. Without it `wl-copy` infers a binary type and the collector never sees a text offer.
- Keep the check in `e2e-headless.sh` that the wl-clipboard bin directory holds no `cat`. `wl-paste` and `wl-copy` exec `cat`, so a collector wrapper whose PATH lacks coreutils loses every capture and re-copy under the service's PATH; the `env -i` run with only wl-clipboard on PATH catches that, and a full developer PATH hides it.
- Do not let a fixture instance that forces write failures run the real `gc`. `run-qml-fixture.sh` fails history saves by making the state directory read-only, and `gc` would tighten the directory's mode and undo that, so the durable instance's collector answers `gc` with a no-op.
- Leave the default text gate at 2 s in `collector_test.py` and `run-qml-fixture.sh`. Every fake `wl-paste` call is a Python startup and one classification makes several, so a multi-read offer can approach the collector's 1 s default by itself.
- Retune the stall tests together when the collector's gate bounds or `NIRI_TIMEOUT_SEC` (0.3 s) change. They set the gate to 250 ms; the per-read delay (0.15 s or 0.2 s) must push the total past the gate, and in `test_slow_first_focus_answer_counts_toward_the_gate` the 0.2 s niri delay must stay under niri's timeout while the 0.03 s reads carry the total past the gate.
